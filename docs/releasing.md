# 版本与更新说明

正式版本同时包含 Git 标签、中文 Release、固定版本镜像、`stable` / `latest` 镜像和服务端部署包。功能分支与 PR 用于检查，不能当作正式版本已发布。

## 版本信息

- `internal/buildinfo/release.json` 保存应用版本、中文功能标题和路由器包修订号。
- `CHANGELOG.md` 保存同一版本的中文更新说明和升级注意事项。开发期间可标记「未发布」，正式打标签前填写发布日期。
- 应用、插件包、镜像版本和 Release 使用同一份版本数据；发布工具只提取当前版本的说明。

例如应用版本 `0.1.10`、包修订号 `3` 对应 Git 标签 `v0.1.10`、插件包 `0.1.10-3` 和镜像 `ghcr.io/yehao9589/remotegate:v0.1.10`。

## 发布步骤

1. 完成代码和必要测试，更新版本文件及 `CHANGELOG.md`。提交与 PR 标题带上版本及功能摘要，例如 `release: v0.1.10 安装更新中心与远程管理`。
2. 推送功能分支并建立 PR。Actions 显示版本明确的 PR 标题，运行摘要展示版本、插件版本和中文更新内容。
3. 代码检查、竞态检查及容器部署验证通过后，将本次完整变更合并到 `main`。
4. 在已合并的提交创建对应版本标签并推送。标签必须与版本文件一致，且当前版本必须有标题、发布日期和更新说明。
5. 标签流水线检查通过后，发布 AMD64 / ARM64 固定版本镜像，更新 `stable` / `latest`，并自动发布带功能标题和中文说明的 GitHub Release。
6. 核对正式 Release、部署包与校验文件、镜像标签都已生成，再通知用户更新。已经公开的版本不覆盖重发；有新改动时递增版本。

正式发布后可在 [GitHub Releases](https://github.com/yehao9589/remotegate/releases) 查看版本号、功能名称、中文说明和下载附件。Release 不单独附加路由器安装包，插件由部署后的管理后台提供。

`main`、手动触发或功能分支构建不会更新 `stable` / `latest`；正式版本标签通过检查后才更新这些标签。普通源码推送、PR 检查通过和正式镜像发布应分别说明实际进度。

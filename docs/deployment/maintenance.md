# 更新、备份与恢复

[返回部署指南](../../DEPLOYMENT.md)

## 镜像版本怎么选

| 标签 | 用途 |
| --- | --- |
| `stable` | 常规部署默认值，跟随通过检查的主分支构建和版本发布 |
| `latest` | 当前主分支或最近版本发布镜像 |
| `v版本号` | 可选，固定某次发布，控制升级时间 |
| `sha-完整提交号` | 固定某个已发布构建，排查或回滚时使用 |

`stable` 的标签会更新，但运行中的容器不会自动升级。仅保存配置或重启原容器不会下载新镜像。

后台“安装包与版本”显示实际服务端版本、提交、构建时间与插件包版本，升级后在这里核对，不用仅凭镜像标签判断。

## 宝塔界面更新

1. 更新前停止 RemoteGate 编排，通过宝塔文件管理备份实际数据目录及原编排配置，备份后重新启动。
2. 检查 compose 的镜像默认值与 `.env` 的 `REMOTE_GATE_IMAGE` 都使用 `ghcr.io/yehao9589/remotegate:stable`；旧 `.env` 固定标签会覆盖 compose 默认值。
3. 使用宝塔“更新镜像”功能重新拉取并重新部署，保留原数据目录。
4. 重新登录，在后台“安装包与版本”检查实际版本，并确认设备恢复连接。

宝塔实例无需在自己电脑执行 PowerShell。修改 `PUBLIC_URL`、后台域名或监听端口后，也需要重新创建容器使环境变量生效。

## 命令行更新

以下命令在**服务器终端**的原编排目录执行：

```sh
docker compose pull
docker compose up -d
docker compose logs --tail=100
```

从源码构建的实例使用[源码教程](source.md#4-后续更新)的构建命令，不能仅用 `docker compose pull` 更新。

## 备份与恢复

管理员、设备、映射、证书和 DNS 凭据都存放在挂载到 `/data` 的服务器目录：

| 内容 | 相对数据目录的路径 |
| --- | --- |
| 管理员账号、密码哈希与后台入口 | `admin.json` |
| 设备、映射及主域配置 | `state.json` |
| 证书、私钥、DNS 凭据与 ACME 账户 | `certificates/` |

宝塔示例为 `/www/RemoteGate/data`，命令行默认是项目 `./data`。以实际 `REMOTE_GATE_DATA_DIR` 为准。备份整个数据目录及 `.env`/编排配置，先停止服务取得一致快照。

下面的命令只适用于数据目录仍为 `./data` 的命令行实例：

```sh
docker compose stop
sudo tar -czf remotegate-backup-$(date +%Y%m%d-%H%M%S).tar.gz data .env
docker compose up -d
```

改过数据路径时按实际路径备份。备份包含秘密凭据，应妥善保管。

恢复或迁移时停止服务，恢复整个数据目录与原配置，再启动。新服务器的域名解析、`PUBLIC_URL` 和服务端连接地址按实际情况调整。

回滚镜像时可使用固定版本标签。新版本数据未必兼容旧版本，必要时同步恢复升级前的数据快照；不要用删除数据目录的方式“修复”安装或登录错误。

## 运行问题

- **不健康**：查看容器日志；修改 HTTP 监听端口后同步修改 `HEALTHCHECK_URL`。HTTPS 端口冲突时调整实际监听，或关闭不用的内置 HTTPS。
- **安装包不可用**：检查是否来自官方镜像或完整源码构建，后台应显示插件文件及可验证版本清单。
- **镜像拉取失败**：核对 `ghcr.io/yehao9589/remotegate` 地址和服务器网络，可改用[源码构建](source.md)。
- **访问或来源错误**：见[首次访问问题排查](access.md#访问问题排查)，不需要重置账号。

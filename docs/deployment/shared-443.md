# 与宝塔共用 443：映射使用系统证书

> 历史 v0.1.5 配置说明：原有内置入口和证书继续保留兼容。新版后台改为只检测公网 HTTPS，不再提供本文中的网页申请或入口迁移按钮。已有宝塔站点的新部署请使用[宝塔证书与检测](external-https.md)，无需迁移其他网站的 443。

[返回部署指南](../../DEPLOYMENT.md) · [首次安装与其他访问方式](access.md)

适用于同一台 Linux 服务器已经运行宝塔 / Nginx 网站，又希望 RemoteGate 的映射直接使用 `https://router.example.com/`，且系统证书续期后自动生效。

**这是一次入口迁移，不是删除宝塔证书。** RemoteGate 接收公网 TCP 443，按 TLS 握手中的域名分流：映射在 RemoteGate 使用系统证书；其他网站的加密连接原样交给宝塔。宝塔继续提供自己的证书、站点和反向代理。HTTP 80 保持原样。

同一 IP 的 TCP 443 不能同时由两个独立服务占用。仅取消宝塔 SSL 证书不会释放监听端口。此方式需要一次调整宝塔的监听，后续增加映射、申请证书和自动续期都在 RemoteGate 操作。

> 本功能适用于 v0.1.5 及以上版本。只有愿意迁移现有监听时才使用本篇；不希望改动现有网站时，请保留原入口并使用独立 HTTPS 端口。

## 1. 先确认条件与回退入口

- 使用官方 Linux host 网络编排，HTTP 后台仍监听 `127.0.0.1:18088`。
- 备份全部宝塔 Nginx 站点配置；记录哪些 IPv4、IPv6 和默认站点监听 443，包括其他软件产生的监听。
- 保持宝塔管理面板或服务器 SSH 可用。迁移期间原网站 HTTPS 会暂时中断，不能只依赖正在迁移的 HTTPS 后台操作。
- RemoteGate 中已安装有效、完整的映射证书。例如 `*.gate.example.com` 覆盖 `router.gate.example.com`，不覆盖 `gate.example.com` 本身或更深一级子域名。
- 如果后台主域名由宝塔提供证书，在“主域名 · 公网 HTTPS”选择“宝塔 / 反向代理”。保留宝塔原证书与续期任务。
- 在后台证书的“接入 HTTPS”打开“与宝塔共用 443”，先阅读监听示例，尚不要启用。

没有宝塔网站、443 空闲的新服务器，直接选择“独立使用 443”，无需本篇迁移。

## 2. 将宝塔 HTTPS 移到内部端口

本篇用 `127.0.0.1:9443` 作为宝塔内部地址。端口必须空闲，并与公网 443 不同。修改**所有**原 443 监听，保留 `server_name`、SSL 证书、反代、WebSocket、站点路径等原设置。

在各 HTTPS `server` 中，将原 `listen 443 ssl;` 改为：

```nginx
listen 127.0.0.1:9443 ssl proxy_protocol;
set_real_ip_from 127.0.0.1;
set_real_ip_from ::1;
real_ip_header proxy_protocol;
```

这些是添加到现有 HTTPS `server` 的监听与真实 IP 设置，**不要覆盖整份站点配置**。原 `default_server` 等参数按站点保留。原 `http2` 设置按所用 Nginx 版本保留；旧版监听上的 `http2` 参数可继续加在这条监听中。

原 `listen [::]:443 ssl;` 也必须迁移或移除，不能遗留公网 IPv6 443。多个站点共用 `127.0.0.1:9443` 时，监听参数须一致，`default_server` 只能按原有默认站点配置。不要同时保留不带 `proxy_protocol` 的同地址监听。

在宝塔检查配置并重载 Nginx；如使用服务器终端，可以执行：

```sh
nginx -t
```

检查通过后通过宝塔重载 Nginx。用服务器终端 `ss -ltnp` 检查：9443 只监听回环地址，公网 TCP 443 已释放。云安全组、防火墙只需允许公网 TCP 443，**不要开放 9443 或 18088**。

真实 IP 使用 PROXY protocol：上方 Nginx 配置必须与 RemoteGate 的“传递真实客户端 IP”开关同时启用。若 Nginx 不具备 HTTP realip 模块，可先选择不传递，移除上述 `proxy_protocol` 和三个 realip 设置，并关闭该开关；原网站仍能访问，但宝塔会把连接来源识别为回环地址，访问日志、限流及基于 IP 的规则会受影响。不要混用两套设置。

宝塔以后添加网站或重新生成配置时，也应继续使用内部地址，不能重新占用公网 TCP 443。保留这份迁移配置备份。

## 3. 启用 RemoteGate 共用入口

### 方式 A：在宝塔界面完成首次启用（无需 HTTP 登录）

如果后台强制 HTTPS，迁移监听后不能进入 RemoteGate，可直接通过宝塔文件管理和 Docker 界面完成首次启用，不必把后台密码通过公网 HTTP 发送。

在持久化数据目录（默认 `/www/RemoteGate/data`，以自己的 `.env` 为准）备份原 `https.json`，创建或编辑**这个文件**为：

```json
{
  "enabled": true,
  "listenAddress": ":443",
  "mode": "shared",
  "fallbackAddress": "127.0.0.1:9443",
  "proxyProtocol": true
}
```

保留原文件权限，数据目录不可作为网站文件目录公开；不要修改或删除 `state.json`、证书或账号文件。上述 `proxyProtocol` 与步骤 2 保持一致。

完成宝塔监听迁移并重载 Nginx，确认公网 443 已释放后，在宝塔 Docker 界面重启 RemoteGate 容器。容器从文件恢复共用入口；启动日志若报告端口占用或配置错误，按文末回退。进入原 HTTPS 后台，接入窗口将显示实际监听状态，以后可以直接在后台修改设置。

### 方式 B：仍有安全后台访问路径时，直接在后台启用

可以通过 SSH 隧道访问本机后台，再在界面保存。HTTP 80 未迁移，但不要在不可信网络通过公网 HTTP 输入密码。

如果需 SSH 隧道，参考[方案 B](access.md#方案-b没有反代使用-ssh-隧道)。已设置 `CONSOLE_HOST` 时，隧道需要让浏览器以该主机名访问：在自己电脑临时 hosts 中将后台域名指向 `127.0.0.1`，使用隧道端口访问；操作后移除临时 hosts。

在“接入 HTTPS → 与宝塔共用 443”填写：

| 设置 | 本篇示例 |
| --- | --- |
| 公网监听地址 | `:443` |
| 宝塔内部 HTTPS 地址 | `127.0.0.1:9443` |
| 传递真实客户端 IP | 开启，与步骤 2 的 Nginx 配置一致 |
| 已完成宝塔内部监听设置并通过配置检查 | 确认完成后勾选 |

点击“保存并启用共用入口”。系统先检查宝塔内部地址能否连接，再绑定公网入口和保存配置。后端未监听、443 被占用或磁盘保存失败时返回错误，不替换 RemoteGate 原入口。它不会自动修改、检查或重载 Nginx，也不能自动恢复先前已经修改的宝塔配置。

配置保存于数据目录 `https.json`，随数据目录持久化，重启后恢复，优先于 `HTTPS_LISTEN_ADDR`。已有 `.env` 的 `HTTPS_LISTEN_ADDR=` 可以保持留空；后台保存后无需重新创建容器。

## 4. 验证原网站和映射

1. 原宝塔后台和其他网站应恢复到原 HTTPS 地址。证书仍是宝塔原证书。
2. RemoteGate 映射选择 HTTPS、443；显示地址例如 `https://router.gate.example.com/`，不用写 `:443`，更不用写 `:8443`。
3. 在“解析接入”用具体映射域名检测公网 HTTPS，确认 DNS 与返回的证书正确。
4. 确认设备在线，再用映射的检测按钮检查内网服务。公网证书验证不等于内网服务连通。
5. 自动续期成功后，新 TLS 连接直接使用系统的新证书，无需导入宝塔或重启入口。

默认分流规则：已配置的映射始终由 RemoteGate 处理；其他有系统证书覆盖的域名可进入 RemoteGate；标为外部管理的主域名、其他网站交给宝塔。若某个其他网站的域名也被系统泛域名覆盖，应使用不重叠的域名范围或单独的具体映射证书，避免入口归属冲突。

共用入口依赖客户端提供可见的 TLS SNI，适用于常规浏览器和设备 HTTPS/WebSocket；无 SNI 的连接交给宝塔。目前仅分流 TCP HTTPS，不代理 UDP HTTP/3；不要为此入口宣告未经配置的 HTTP/3。慢握手和宝塔透传连接合计最多 256 个，达到上限会拒绝新连接；原宝塔长连接也计入此限制。

## 回退与排查

- 宝塔站点的 SSL 保存或配置重建导致 443 再次被占用：检查并恢复内部监听，不要删除证书。
- 宝塔网站握手失败：检查内部地址、Nginx 是否运行、两边 `proxy_protocol` 设置是否一致。
- 映射证书不匹配：确认具体域名覆盖、映射归属与公网 DNS，检查是否仍访问了旧入口。
- 回退：在 RemoteGate 停用共用入口；恢复全部宝塔站点备份中的 443 监听；检查通过后重载 Nginx。停用共用入口会暂时中断所有经此入口访问的网站。

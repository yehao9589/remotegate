# 安装路由器插件与添加映射

[返回部署指南](../../DEPLOYMENT.md)

本篇从**服务端已经安装、后台能够登录**开始。服务端部署与路由器插件安装是两步，不必在路由器上运行 Docker 服务端。

## 设备工作台

设备卡片支持编辑名称和备注、置顶、隐藏或复制设备 ID。全局搜索可查名称、备注、连接 IP 和映射；卡片内可按域名、内网地址、备注与启停状态筛选映射。“复制新增映射”复用内网服务和端口，需要填写新的访问域名后保存。

卡片顶部展示连接 IP，默认遮蔽部分内容，可显示完整地址或直接复制。公网地址自动识别所属网络运营商，支持 IPv4 / IPv6，并可按运营商搜索；离线设备标注“上次 IP”。本机、内网、共享与保留地址会明确分类，不查询公网运营商。经过 VPN 或代理时，显示的是服务端看到的连接出口。

运营商识别由服务端向 [RIPEstat](https://stat.ripe.net/docs/data-api/api-endpoints/prefix-overview) 查询公网 IP 所属网络，电信、移动、联通等已识别名称以中文展示；其他网络保留登记名称，多来源网络一并显示。仅提交公网 IP，不提交设备 ID 或令牌。成功结果缓存 24 小时并保存在私有数据目录，失败显示“未知”并在 5 分钟后重试；查询不阻塞设备连接或页面刷新。`.env` 设置 `IP_OPERATOR_LOOKUP=false` 可关闭外部查询。

“连接详情”显示最近连接/断开时间、本次在线时长、最近响应与隧道往返延迟。连接来源 IP 由服务端读取；同机反代时只接受回环来源的有效 `X-Real-IP`。系统、架构、主机名和配置的出口网卡从 v0.1.9 插件起支持上报。服务端与插件均更新至 v0.1.15 后，还会显示实际出口：自动选择时显示“自动选择 · 实际：pppoe-wan”等实际连接网卡，离线后标注“上次实际”；旧插件未上报时明确提示，不把配置值当作实际出口。

“检测连接”检查路由器与服务端的隧道，兼容旧插件，不证明内网服务或公网入口可用。“重新连接”会短暂中断访问，等待客户端自动重连，保留设备凭据与映射；离线或更新中的设备不执行此操作。客户端无法自行恢复时，应检查路由器进程和网络，不要重复添加设备。

## 1. 确认服务器地址

填写路由器能够访问的服务端地址，例如 `https://gate.example.com`。它不包含 `/admin` 等后台路径，也不是你电脑的 `127.0.0.1` 或 SSH 隧道地址。

如果走宝塔反代，代理需转发 `/api/agent/connect` 的 WebSocket 升级请求。独立或[共用 443](shared-443.md) 入口的外部地址为 `https://gate.example.com`；只有选择非标准端口时才需带该端口。

## 2. 选择插件安装方式

| 方式 | 操作 |
| --- | --- |
| 一键安装 | 设备工作台点击添加设备，填写可访问的服务器地址，在路由器终端执行后台生成的命令 |
| iStore 手动安装 | 从后台“安装与更新中心”下载版本化 `.run` 包，在路由器 iStore → 手动安装上传；随后在“服务 → RemoteGate”填写连接信息并启用 |

安装后检查插件页面连接状态，并回到后台确认设备在线。未完成首次接入的设备不进入已安装设备列表。

从 v0.1.13 起，手动升级已有且启用的完整配置时，安装完成会自动启动新客户端。首次安装或未启用、信息未填全时，仍需填写后保存并应用。

若插件显示身份验证失败（401），请核对服务器地址、设备 ID 和令牌是否来自同一后台、同一个设备。未首次上线的接入凭据会在服务端重启后失效；需要接入新设备时，从当前添加设备向导的“iStore 手动安装”查看新凭据，在路由器填写并保存应用，无需重复安装插件。已成功绑定的设备凭据会随数据目录保留。

从 v0.1.12 起，插件区分“正在连接”“已连接服务器”“重连中”和“客户端未运行”，显示最近成功连接时间、失败原因及下次重试时间。只有隧道握手成功并持续收到服务器心跳，才显示绿色的已连接状态；单纯进程运行不会视为在线。页面每 5 秒读取一次，读取失败会清除之前的已连接提示。

### OpenClash Fake-IP 兼容

当系统 DNS 为服务端域名返回 `198.18.0.0/15` 虚拟地址，或公网域名解析失败时，v0.1.12 客户端自动通过[阿里云公共 DNS](https://www.alidns.com/)的 HTTPS 接口查询真实地址，再使用原域名建立连接并校验证书。加密 DNS 连接同样使用配置的出口策略；加密解析成功本身不能证明流量绕过了代理。仅查询配置的服务端域名，不发送设备令牌，也不改变内网映射的 DNS 解析。

此解析处理同时用于隧道和插件更新，不需要修改 hosts。自定义 Fake-IP 地址池、受限的 DNS 出口及特殊策略路由仍需单独验收；解析失败时会显示错误并自动重试，不会跳过 HTTPS 证书验证。

**旧版已经因 Fake-IP 断连时**：服务端更新后，从后台下载新版 `.run` 插件包，通过现有的其他连接通道在路由器 iStore 手动安装一次，然后进入“服务 → RemoteGate”保存并应用，保留原配置并启动新客户端。旧版更新程序同样受 Fake-IP 影响，仅更新服务端镜像不会替换路由器上的旧客户端。

新版“高级设置 → 出口网卡”自动选择直连出口：优先使用 WAN / WAN6 的有效默认路由；WAN 未接线或没有默认路由时，继续查找 LAN 等接口的上联网关，即使系统保留了未使用的 WAN 配置也能连接。IPv4 / IPv6 分别选择，不自动使用 TUN / VPN 默认路由。需要固定出口时，从系统网卡下拉列表选择实际设备；列表显示网卡名、启用状态和 IP。重新打开页面会重新读取列表；暂时不可用的原配置会保留，选择后保存并应用。

自动识别以接口状态和有效默认路由为依据，不等同于对所有接口进行互联网测速或探测。如果某接口仍显示已连接且保留默认路由，但上游实际故障，可以先手动选择已确认可联网的接口。

### OpenClash 重启与短暂断线

OpenClash 完整重启会调整系统防火墙、策略路由和 DNS；即使平时走国内出口，也不能据此保证重启期间完全无感。新版在 FW4 上将连接标记恢复与原地址 NAT 绑定放在独立的 `remotegate_direct` 表，保留已有直连连接；监听防火墙规则变化及时修复共享链，并每 2 秒补查。FW3 继续使用专用标记绕过规则及周期修复。仅保护 RemoteGate 的服务端、加密 DNS 和更新连接，不改变其他应用的代理设置。

网络短暂波动时，后台、普通用户页面和插件先显示“正在恢复连接”，保留已有数据，给出 30 秒恢复时间；成功后自动恢复显示，持续失败才提示错误。认证、权限或证书错误仍立即显示。上下线记录保留真实变化，不将缓冲期伪装成在线。

映射在最近一次断线的 30 秒窗口内，可以先等待隧道恢复再发出请求；等待结束会重新检查映射及访问授权。已经发出的表单、上传等写入操作不会自动重复，以免执行两次。GET 页面遇到隧道中断时可显示恢复页，用 HEAD 探测恢复后重新打开原页面。

规则保护不覆盖宽带断网、网卡重置、整套路由或连接跟踪被外部程序清空等所有情况。IPv4 / IPv6、WAN / LAN、代理故障及共享规则重建已通过隔离网络测试；真实路由器的 OpenClash 完整重启仍需按实际模式验收。此改动需要升级服务端和路由器插件，仅刷新网页不会替换路由器上的客户端。

Release 不单独发布插件包，官方服务端镜像已经内置 x86_64、ARM64、ARMv7 包；后台下载与一键安装使用同一套版本文件。

完整的安装模板、精简下载、批量更新、记录与兼容回退说明见[安装与更新中心](install-center.md)。

### 插件在线更新

从 v0.1.8 开始，更新插件有两个入口：

- **路由器**：服务 → RemoteGate → 插件更新 → 检查更新 → 立即更新。
- **管理后台**：设备工作台 → 更新插件，或安装与更新中心 → 对应设备的更新插件按钮。

先更新服务端镜像，新的镜像会携带同版本的安装包。插件从自己配置的服务端获取版本和文件，不直接下载 GitHub 的最新包；服务器未提供更高版本时不会更新，也不会降级。只有点击确认才执行更新。

插件服务器地址使用有效证书的 HTTPS 地址，例如 `https://gate.example.com`。公网 HTTP 或跳过 TLS 验证的配置无法在线更新；本地测试允许回环 / 私有 IP 的 HTTP。仍使用公网 HTTP 的设备应在路由器页面改为同一服务器的 HTTPS 地址，保存并应用。

**旧版首次升级**：v0.1.7 及之前的插件没有更新执行器。后台“更新插件”会提供首次升级命令，在路由器 SSH 以 root 执行一次。该命令有效期 15 分钟，只能下载一次；失效后重新生成。它只升级已安装的插件，保留原设备 ID、令牌与连接配置，不要重新添加设备。

更新过程中隧道会暂时断开，后台保留原有映射。关闭页面不会取消已发起的更新，可以再次打开查看阶段。

显示“已启用失败自动回滚”的插件会先备份旧版，再验收新版连接与心跳；安装或验收失败会恢复旧插件、原 UCI 配置和开机启用状态。旧插件需先升级一次，之后的在线更新才支持。具体范围见[更新失败自动恢复](install-center.md#更新失败自动恢复)。更新日志位于 `/var/run/remotegate-update/install.log`，路由器重启后会清除。

此功能适用于当前安装包支持的 x86_64、ARM64、ARMv7 与 opkg 系统；不支持 APK 系统或原本只手动运行客户端二进制的设备。

## 3. 添加设备访问域名

1. 在在线设备下展开“访问域名”，点击添加域名。
2. 填写具体子域名，例如 `ceshi01.example.com`，不是 `*.example.com`。
3. 内网地址与端口填写设备能够访问的目标，例如 `http://127.0.0.1` 与 `80`，另一条映射可以填 `16601`。
4. 公网协议和端口应与[实际 HTTPS 入口](access.md#设备映射的-https-入口)一致。填写协议和端口本身不会开启服务器监听或修改防火墙。
5. 保存后打开公网访问地址，或使用映射检测功能。

这里的内网 `127.0.0.1` 指运行插件的路由器。NAS 等其他设备应填写路由器可达的 LAN IP。

路由器主动连接服务器，不需要路由器公网 IP 或入站端口转发。新版客户端为自身隧道、加密 DNS 和插件更新建立独立的带标记路由，并绑定选中的出口；兼容 OpenClash 的 IPv4 / IPv6、FW3 / FW4 出站链。每 10 秒重新检查规则，处理 OpenClash / 防火墙重载。原全局默认路由、订阅规则和其他设备流量保持原有处理方式。

该保护需要更新路由器插件，仅更新服务端镜像不会替换旧客户端。WAN、LAN 等接口均无有效直连出口，或存在规则冲突、保护配置失败时，会明确报错并重试，不静默回退代理。插件显示保护配置与实际绑定接口，服务端记录的连接来源用于核对公网出口；不会仅凭 DNS 模式声称“已验证直连”。手动选择 VPN 网卡仍按明确选择执行，不视为宽带直连。

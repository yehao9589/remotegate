# 映射访问保护

HTTPS 负责传输加密；“需要后台登录”决定谁可以通过 RemoteGate 访问内网网站。这两项可以同时启用。

## 默认行为

- 新增映射默认开启保护；升级后，尚未配置访问权限的已有映射也统一开启保护。
- 在设备卡片展开“访问域名”，编辑映射的“访问权限”。只有明确用于公开访问的网站才选择“公开访问”。
- 保护使用 RemoteGate 管理员账号。它不会代替路由器、NAS 等目标网站原有的登录；首次使用时可能还需登录目标网站。

## 访问流程

1. 打开映射的 HTTPS 地址。
2. RemoteGate 跳转到后台验证身份。已有有效后台登录时自动通过；未登录时输入管理员账号密码。
3. 浏览器自动回到原网站、原路径和查询参数。只有当前映射获得访问授权，其他映射会各自验证。

管理员 Cookie 保持在后台域名，映射域名只接收独立的 HttpOnly、仅本主机可用的通行 Cookie。后台凭证、通行 Cookie、一次性验证参数不会转发给内网网站；目标网站自己的 Cookie 正常传递。

验证请求最多有效 5 分钟，返回的验证代码最多有效 1 分钟、只能使用一次，并与发起验证的浏览器绑定。通行会话最长与原后台登录一致（12 小时）；退出后台、会话过期或重启服务后，后续请求需要重新验证。修改密码或后台入口会使所有旧后台会话及关联通行授权失效。

停用、删除映射，或修改映射域名、内网目标、设备、公网协议/端口、访问权限，也会使旧通行授权失效。修改备注不会要求重新验证。切回登录保护后，不会恢复之前的授权。

退出后台会清除当前服务的全部映射通行授权，也包含重复登录前签发的旧授权。其他浏览器如果仍保有有效后台登录，下次打开映射可自动再次验证，无需重复输入密码。

## 部署要求

- 公网保护必须使用 HTTPS，证书及反向代理继续按现有部署提供。此功能无需路由器插件升级。
- 本机 `localhost`、`*.localhost` 与回环地址预览允许 HTTP；公网 HTTP 映射会暂停访问并提示配置 HTTPS，也可由管理员明确改为公开访问。
- 优先通过 `PUBLIC_URL=https://gate.example.com` 或 `CONSOLE_HOST=gate.example.com` 指定后台认证地址，不含后台路径。已有反代须保留正确的 Host 和 HTTPS 协议信息。
- 未配置上述地址时，管理员首次通过 HTTPS 登录后台、加载设备列表后，会将当前地址绑定为已有映射的认证入口。绑定完成前映射拒绝访问，避免认证地址不明时开放内网。

不更改已有宝塔站点配置或证书。若现有反代和证书已经支持该映射，保持原样即可。

## 接口与兼容性

未授权的网页导航会跳转验证；未授权的浏览器脚本请求、声明接收 JSON 的请求及修改请求返回 `401`，`Location` 响应头给出验证入口。先用浏览器完成验证，再重新发起原请求；RemoteGate 不保存并重放修改操作。

映射域名下的所有路径均属于目标应用，包括 `/api/...`。它们不会进入 RemoteGate 管理接口。跨来源的修改请求被拒绝，避免其他网站借用当前访问授权操作设备。

目前验证身份是 RemoteGate 管理员，没有单独的访客账号或分享密码。通行凭证仍应视作敏感信息；不要手动复制 Cookie 给他人。已下载到浏览器的内容或已发往目标设备的操作不会因退出而撤回。

# 安装与更新中心

从后台侧栏打开「安装与更新中心」，统一管理设备接入、插件更新、安装模板和执行记录。

## 安装设备

「连接新设备」会打开安装向导。填写设备名称、选择安装模板，确认路由器能够访问的服务器地址，然后在路由器 SSH 终端执行生成的命令。

一键安装会检查 root 权限、opkg、CPU 架构、下载工具、可用空间和服务器连接；按架构下载并校验插件，应用模板后启动客户端。后台显示设备实际报告的阶段，只有设备完成认证连接、上报目标版本后才显示成功。已有不同设备绑定的路由器不会被新安装命令覆盖，应使用保留配置的升级功能。

无需 SSH 时，选择「系统 → 软件包（.ipk）」，再按路由器固件架构下载，在 QWRT / OpenWrt 的「系统 → 软件包 → 上传软件包」安装。64 位 ARM 固件选择 ARM64，32 位 ARM 固件选择 ARMv7，不要仅按 CPU 型号判断；IPK 没有通用包。

使用 iStore 时，选择「iStore / SSH（.run）」，下载通用包或对应架构的精简包，在「iStore → 手动安装」上传。`.run` 不适用于「系统 → 软件包」，修改后缀也无效。安装完成后进入「服务 → RemoteGate」填写设备连接信息。

IPK 从同一份已校验安装器提取，提供独立的 SHA-256 校验值，不包含账号、设备令牌或预设服务器地址。

通用包包含三个架构；精简包只包含对应架构。精简文件由服务端从镜像内已校验的通用包生成，不增加镜像中的重复安装包层。路由器新版在线更新和一键安装会自动匹配架构，旧插件保留通用包升级方式。

## 安装模板

模板可保存默认服务器地址、SSH / 文件管理开关、开机启动和出口选择方式。默认开启远程管理及开机启动；显式关闭的设置会保留。

服务器地址留空时，由安装向导填写。出口可设为「自动选择」或「安装时从系统网卡列表选择」；后者在执行命令时显示实际网卡，不需要预先手填设备名。

模板不保存设备 ID、令牌、SSH 密码或私钥。修改、删除模板不改变已安装设备的设置。内置「标准接入」模板可复制后自定义。

## 设备更新和检查

在「设备更新」中搜索、筛选并选择待升级设备。批量任务逐台执行，确认当前设备的新版本重新连接后再处理下一台。默认某台失败时暂停，可继续剩余设备；暂停或取消队列不会中断已经发起的安装。

服务端重启后，未完成的批量队列会暂停，需先核对设备实际版本再继续。离线、锁定、正在更新或无需升级的设备不能加入新队列。

「安装检查」读取设备的系统权限、包管理器、原配置、服务器连接、CPU 架构、可用空间与当前任务。需先将插件升级到 0.1.10-3 或更高的对应版本。

### 在插件内上传更新

从插件 `0.1.18-3` 起，在路由器「服务 → RemoteGate → 插件更新 → 手动上传更新包」选择 `.ipk` 或 `.run`（最大 15 MiB），点击「上传并校验」，核对当前与目标版本、适用架构和文件 SHA-256，再点击「确认更新」。仅使用可信来源的 RemoteGate 安装包；校验值用于与下载来源核对。

安装包在本机校验，不从服务端下载；通用 `.run` 只取当前架构的 IPK，不执行上传文件的脚本头。只允许升级到更高版本，拒绝错架构、其他插件、无关文件或重复路径。操作需要路由器 root 管理员登录，并有会话校验。

手动更新与在线更新使用同一套旧版备份、配置保留和失败回滚流程，不能同时执行。已启用的客户端会验收新连接和心跳，持续无法连接时自动回滚；已停用的插件保留停用设置。更新一旦发起，关闭网页不会取消。首次获得此入口，需从旧插件的安装方式升级到 `0.1.18-3` 或更高版本一次。

### 更新失败自动恢复

插件提示“已启用失败自动回滚”后，从插件或后台发起的在线更新，以及插件内手动上传更新，按以下顺序执行：

1. 校验下载文件，备份当前路由器实际安装的插件、启动脚本与连接配置。备份不完整或空间不足时停止更新。
2. 安装新版并恢复原配置，保留设备 ID、令牌与开机启动设置。
3. 检查新版客户端及真实服务器心跳，连接稳定后才显示完成。连接验收最多等待 90 秒，不会因为一次短暂断线就立即回滚。
4. 安装、启动、版本检查或连接验收失败时，恢复旧插件，再检查旧版连接。失败结果保留在更新记录中，不会自动重试同一更新。

旧插件需先升级一次，之后的在线更新才具备这项保护。通过 iStore 或系统软件包页面直接安装 `.run` / `.ipk` 不经过此更新执行器，也不提供此自动回滚。主动停用的服务保持停用，不强制要求上线。

如果旧版也无法连接，页面会明确提示检查网络和服务端；如果恢复旧版失败，会保留本机备份位置并停止后续在线更新，需人工恢复。备份位于路由器临时目录，本功能不覆盖更新过程中断电、重启或更新执行器被强制终止的情况。

## 版本锁定和回退

锁定后，该设备不能从管理后台或路由器在线更新；解锁后恢复。锁定的是 RemoteGate 管理的更新流程，手动通过 opkg 安装属于路由器自身操作。

服务端保留最近五个已校验通用包和所需架构缓存；正在使用的任务包会保留。回退只允许同一客户端版本的更早包修订号，例如 `0.1.10-3 → 0.1.10-2`，不跨客户端版本回退。目标包必须存在于服务端历史缓存，设备需支持新版回退工具，且必须在线并未锁定。

更新和回退都会保留原设备 ID、令牌、连接配置与开机启用状态。回退至旧插件后，某些新增工具可能暂不可用，可再次升级恢复。

## 历史记录与诊断

保留最近 200 条安装、更新与回退记录，每条显示版本变化、时间、观察到的阶段、结果及错误原因，可下载 JSON 诊断报告。阶段记录来自实际报告或检查，不代表未观察到的阶段已经完成。

模板、版本策略和记录位于数据目录中的 `package-center.json`；历史包位于 `packages/`。更新镜像时保留原数据卷，这些信息会在服务端重启后恢复。诊断报告不导出设备配置、令牌或 SSH 凭据。

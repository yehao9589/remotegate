# 后台地址、首次登录与访问排查

[返回部署指南](../../DEPLOYMENT.md)

**已有可用的 HTTPS 域名反代，就直接用域名安装，不需要再建 SSH 隧道。**

| 你的情况 | 使用哪种方式 |
| --- | --- |
| 已有宝塔 / Nginx HTTPS 站点 | 方案 A：通过域名访问 |
| 还没有可用的反代 | 方案 B：通过 SSH 临时访问，再准备公网入口 |

## 方案 A：已有宝塔/Nginx 反代

1. 容器配置 `CONSOLE_HOST=gate.example.com`，只填自己的后台域名。
2. `HTTPS_LISTEN_ADDR` 留空，关闭新实例的内置 HTTPS，由现有站点提供证书。
3. 站点反代到 `http://127.0.0.1:18088`，保留原始 Host 和 WebSocket 配置。
4. 重新部署容器后，打开 `https://gate.example.com/install` 创建管理员。
5. 安装完成后使用保存的后台地址，例如 `https://gate.example.com/admin`。

完整可复制配置：[宝塔安装教程](baota.md)。

**使用自定义公网端口时**，另外填写完整的 `PUBLIC_URL`，例如 `https://gate.example.com:18443`；不带 `/admin`。域名或端口改动后，要重新创建容器。默认 80/443 入口下通常留空即可。

## 方案 B：没有反代，使用 SSH 隧道

此方式用于临时初始化管理员或排障，**不会自动建立公网 HTTPS**。

### 1. 服务器上的初始化设置

容器中的 `CONSOLE_HOST`、`PUBLIC_URL`、`HTTPS_LISTEN_ADDR` 均留空，HTTP 保持监听 `127.0.0.1:18088`。

### 2. 在自己的电脑上执行

在**自己电脑的终端或 PowerShell**执行，不是在服务器终端执行：

```sh
ssh -N -L 18090:127.0.0.1:18088 root@服务器公网IP
```

替换 SSH 用户和服务器 IP。SSH 不是 22 端口时加上 `-p 实际端口`。连接后保持这个窗口打开，再用浏览器访问：

```text
http://127.0.0.1:18090/install
```

这是通过 SSH 加密隧道访问服务器；不是电脑上的另一个 RemoteGate 测试后台。如果 18090 已被占用，替换命令中的第一个端口，并同步修改浏览器地址。

### 3. 准备正式访问入口

初始化后，为后台域名准备有效 HTTPS 证书和反代，再按方案 A 设置域名并重新部署。之后改用正式域名登录，关闭临时 SSH 窗口。

## 管理员账号与自定义入口

- 默认账号填写 `admin`，首次安装可以更改；密码至少 8 个字符。
- 后台路径默认 `/admin`，也可改为 `/my-panel`，安装后请收藏。
- `/install` 只用于首次创建管理员；已安装时使用原后台入口。
- 修改密码或入口，在“账号与入口”操作，需要验证当前密码，并会退出所有登录会话。
- 重新部署时保留数据目录，原账号和入口会继续保留。

路由器的服务器地址不带后台路径：后台为 `https://gate.example.com/my-panel` 时，路由器仍填 `https://gate.example.com`。

## 设备映射的 HTTPS 入口

后台能打开，不代表每个映射域名都配置好了。宝塔用户继续按[泛域名与 HTTPS 教程](external-https.md)完成这几项：

1. DNS 主域名和泛解析指向服务器。
2. RemoteGate 对应站点绑定主域名及泛域名。
3. 证书覆盖主域名及对应子域名，并已在站点启用。
4. 反代保留原始 Host，映射填写实际公网协议和端口。

标准 443 地址例如 `https://router.gate.example.com/`，浏览器访问时不用额外写端口。证书申请和续期在实际 HTTPS 入口处理，RemoteGate 只检查公网结果。

## 访问问题排查

| 现象 | 怎么处理 |
| --- | --- |
| 请求来源不匹配 | 检查 `CONSOLE_HOST` / `PUBLIC_URL` 是否与实际域名、端口一致；修改后重新部署。本篇反代应与容器在同一台服务器上 |
| `/install` 返回 404 | 如果已安装，使用保存的后台入口；不要删除数据重新安装 |
| 后台能打开，映射打不开 | 检查映射域名解析、证书、站点绑定和 Host 转发，再检测设备内网目标 |
| 返回 `unknown host` | 请求中的域名未匹配后台或启用的映射；检查反代是否把 Host 写死为 `127.0.0.1` |
| 443 提示已被占用 | 使用已有 HTTPS 反代时关闭 RemoteGate 内置监听；不要停止其他网站来腾端口 |

<summary>旧实例与特殊配置</summary>

- 旧实例保存过内置入口设置时，以数据目录的 `https.json` 为准，仅修改环境变量不一定关闭该入口。先备份并核对原部署方式，不删除整个数据目录。
- 后台域名已配置时，直接用 SSH 的本地 IP 访问可能不匹配主机名。应让浏览器以原后台域名访问隧道；相关例子见[历史入口维护](shared-443.md)。
- 历史内置 HTTPS 实例参考[原配置说明](standalone.md)，不照搬其中旧版网页的证书申请步骤。
- 环境配置只帮助程序识别地址，不会自动申请站点证书；`PUBLIC_URL` 也无法恢复已被反代丢掉的映射域名。
